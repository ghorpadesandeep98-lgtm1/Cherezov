# Публикация сайта

Три шага: почта → таблица (по желанию) → Vercel. Всё, что нужно от кода, уже сделано:
как только переменные окружения появятся, форма начнёт доставлять заявки без правок.

---

## 1. Почта через Gmail

Заявки уходят по SMTP от имени вашего Gmail-ящика на адрес из `LEAD_EMAIL_TO`.
Обычный пароль от аккаунта Google для SMTP не работает — нужен **пароль приложения**.

1. Включите двухэтапную аутентификацию: [myaccount.google.com/security](https://myaccount.google.com/security)
   → «Вход в аккаунт Google» → «Двухэтапная аутентификация». Без неё пункта с паролями
   приложений просто не будет.
2. Откройте [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords).
   Введите название (например, `Сайт КД`) → «Создать».
3. Google покажет 16 символов четырьмя группами. Скопируйте их **без пробелов** — это
   значение `SMTP_PASSWORD`. Второй раз посмотреть пароль нельзя, только создать новый.
4. Заполните переменные:

   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=ваш-ящик@gmail.com
   SMTP_PASSWORD=шестнадцатьсимволов
   LEAD_EMAIL_FROM=ваш-ящик@gmail.com
   LEAD_EMAIL_TO=468070@mail.ru
   ```

**На что напороться легко:**

- `LEAD_EMAIL_FROM` должен совпадать с `SMTP_USER`. Любой другой адрес Gmail молча
  перепишет на аутентифицированный — письмо уйдёт, но «от кого» будет не то, что вы ждали.
- Если ящик в Google Workspace, администратор домена может запрещать пароли приложений —
  тогда пункт в настройках недоступен, и вопрос решается на стороне админа.
- Лимит бесплатного Gmail — порядка 500 писем в сутки. Для формы обратной связи с запасом.

## 2. Google Таблица

Необязательный второй канал: если его не настроить, заявки всё равно приходят письмом.
Пишем от имени **сервисного аккаунта** — отдельного «робота» Google, у которого есть
свой e-mail и ключ. Ваш личный аккаунт при этом не участвует.

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и создайте проект
   (выпадающий список проектов вверху → «New project» → имя, например `kd-site` → Create).
2. Включите API таблиц: «APIs & Services» → «Library» → найдите **Google Sheets API** → Enable.
   Без этого шага запросы будут отбиваться с ошибкой доступа.
3. Создайте сервисный аккаунт: «APIs & Services» → «Credentials» → «Create credentials» →
   **Service account**. Имя любое, роль на шаге «Grant access» **не нужна** — Done.
4. Возьмите ключ: откройте созданный аккаунт → вкладка «Keys» → «Add key» → «Create new key»
   → тип **JSON** → Create. Файл скачается один раз, второй раз его не выдадут.
5. Откройте скачанный JSON. Оттуда нужны два поля:
   - `client_email` (вида `имя@проект.iam.gserviceaccount.com`) → `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `private_key` (длинная строка от `-----BEGIN PRIVATE KEY-----`) → `GOOGLE_PRIVATE_KEY`,
     целиком, вместе с последовательностями `\n` внутри
6. Создайте таблицу на [sheets.new](https://sheets.new). Переименуйте нижнюю вкладку листа
   в **Заявки** — именно это имя стоит в `GOOGLE_SHEETS_RANGE`.
7. Нажмите «Настройки доступа» и добавьте `client_email` из шага 5 как **Редактора**.
   Это ключевой момент: без доступа к конкретной таблице сервисный аккаунт её не видит.
8. Скопируйте ID таблицы из адресной строки — это кусок между `/d/` и `/edit`:
   `docs.google.com/spreadsheets/d/`**`1AbC...XyZ`**`/edit` → `GOOGLE_SHEETS_ID`.

Строка пишется в колонки A–E: время (Москва), имя, почта, телефон, источник.
Шапку можно подписать вручную — код дописывает строки снизу и заголовок не трогает.

## 3. Vercel

1. Сначала **влейте PR** — Vercel будет собирать продакшен из ветки по умолчанию.
2. [vercel.com/new](https://vercel.com/new) → «Import Git Repository» → выберите
   `ghorpadesandeep98-lgtm1/Cherezov`. Если репозитория нет в списке, нажмите
   «Adjust GitHub App Permissions» и дайте доступ к нему.
3. Framework Preset определится сам — **Next.js**. Root Directory `./`, команды сборки
   и вывода менять не нужно.
4. До первого деплоя раскройте «Environment Variables» и вставьте переменные из
   `.env.example` (заполненные по шагам 1–2). Отметьте окружения Production и Preview.
   `GOOGLE_PRIVATE_KEY` вставляйте как есть — код понимает и `\n` внутри строки,
   и настоящие переводы строк.
5. Deploy. Через минуту получите адрес вида `cherezov.vercel.app` — на нём уже можно
   проверить форму.
6. Домен: Settings → Domains → Add. Vercel покажет, какие DNS-записи добавить у
   регистратора; после их применения сертификат выпустится сам.
7. Когда домен заработает, впишите его в `NEXT_PUBLIC_SITE_URL` (без слэша на конце) и
   **сделайте передеплой**: Deployments → «…» → Redeploy. Это важно — переменные с
   префиксом `NEXT_PUBLIC_` подставляются во время сборки, а не при запросе, поэтому
   без пересборки в canonical, Open Graph и sitemap.xml останется старое значение.
   То же касается `NEXT_PUBLIC_YANDEX_METRIKA_ID`.

### Проверка после деплоя

- отправьте заявку с сайта: письмо должно прийти на `LEAD_EMAIL_TO`, строка — появиться
  в таблице;
- если форма показывает ошибку, откройте в Vercel Logs запрос к `/api/lead` — код пишет
  туда причину по каждому каналу отдельно (503 значит, что не настроен ни один канал);
- `https://ваш-домен/robots.txt` и `/sitemap.xml` должны отдавать боевой адрес, а не localhost;
- вставьте ссылку на сайт в мессенджер — должна развернуться карточка с героем.

## Что осталось за пределами кода

- **Тексты `/privacy` и `/consent` должен вычитать юрист.** Написаны по типовой структуре
  152-ФЗ на реквизитах из макета.
- **Локализация персональных данных.** Часть 5 статьи 18 Закона № 152-ФЗ требует, чтобы
  базы с данными граждан России находились на серверах в России. Vercel, Gmail и Google
  Таблицы этому не соответствуют. Из политики убрано утверждение о хранении в России,
  чтобы там не было неправды, но сам вопрос остаётся: его нужно обсудить с юристом и,
  возможно, перенести приём заявок в российский контур (почта на российском хостинге,
  таблица заменяется на базу у российского провайдера). Это решение о рисках, а не
  о коде — за пять минут его не принять.
